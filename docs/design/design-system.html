Unitati

One system. Full context.

Guidelines

One system for IT teams: assets, tickets and projects in a single app, with the relations between them always in view. The design is calm, dense and precise: a tool technicians keep open all day. Color is reserved for meaning (which module a record belongs to, what state it is in); everything else is ink on neutral surfaces.

Tagline: One system. Full context.

Brand

  • The product name is Unitati, written with a capital U in the wordmark and in running text. Never all caps, never "UNITATI" or "UniTati".
  • The mark is a U drawn as one stroke split in two: the blue stem (logo-blue) for assets, the green stem (logo-green) for projects, and the violet dot (logo-violet) at the bottom for the service desk, the point where both meet. A white ring separates the dot from the stems.
  • Construction: stems 80 wide and 90 apart, round caps, inner and outer arcs concentric (radii 45 and 125); the dot is as wide as a stem; both stems and the dot end on the same baseline. Details in assets/Logos/README.md.
  • Use unitati-lockup.svg on light grounds and unitati-lockup-inverse.svg on dark; unitati-lockup-tagline.svg (and its inverse) where the tagline belongs, such as the login screen and docs; the mark alone (unitati-mark.svg) in the sidebar and favicon; unitati-app-icon*.svg for PWA and store icons.
  • The wordmark is Unbounded Bold (700), outlined, tracked -0.02em. When the name sits beside the mark in live UI (sidebar), set it in font-display at 700 with the same tracking.
  • Gradients exist only inside the mark and the violet app icon. The UI is flat: no gradient buttons, backgrounds or borders.

Content fundamentals

  • Audience: IT technicians and admins (2 to 30 people) and the employees who raise tickets. Write for someone busy fixing something.
  • Voice: direct, specific, calm. Say what happened and what to do next. No jokes in errors, no exclamation marks, no emoji.
  • Person: address the user as you; the app never says we or I. Spanish UI uses tú; Catalan uses tu.
  • Casing: sentence case everywhere (New ticket, Related records), except table headers, relation labels and nav sections, which are uppercase caption.
  • Buttons: verb first, outcome not mechanism: Close ticket, Link asset, Retire asset. Never Submit, OK, Click here.
  • Records: always refer to a record by its ID plus title (TCK-1093 Laptop doesn't wake from sleep). IDs are prefix + zero-padded number: AST- assets, TCK- tickets, PRJ- projects.
  • Errors: what went wrong and how to fix it, in one line: That date doesn't exist. Use dd/mm/yyyy.
  • Empty states: one sentence on what will appear here and the action to start: No assets yet. Import a CSV or add the first one.
  • Numbers and dates follow the user's locale via Paraglide. In es and ca: decimal comma, thousands dot (1.284, 1.234,50 €), dates dd/mm/yyyy, 24-hour time.
  • Languages: UI in es, ca and en. Code, docs and this system are in English.

Color

Two themes, light and dark, with the same token names. Every text token holds 4.5:1 on every surface-* and on its own *-soft ground in both themes; border-strong and focus hold 3:1.

  • Surfaces: surface-0 is the canvas, surface-1 the panels, tables and inputs, surface-2 the sidebar, table headers and hover. Separate regions with border, not shadows.
  • Ink: ink for text and icons, ink-muted for metadata, placeholders and column headers. Nothing lighter than ink-muted for text.
  • Action: the primary button is ink (action, on-action) with its icon in an action-accent disc, the mark's dot. One primary action per region.
  • Brand: brand for links, the active nav item, selection and focus. on-brand for text on it.
  • Domains: each module owns a hue and uses it only for its records: asset (blue, same as brand), desk (violet), project (green), each with a *-soft background. They appear in record chips, icons, nav dots and timeline dots, never on buttons or page backgrounds.
  • States: success, warning, danger, each with *-soft. Always paired with a word or icon. success and project are both green, so a state never relies on hue alone.
  • Identity: logo-blue, logo-violet, logo-green are for the mark, the cover and marketing only. logo-green fails as text (1.9:1 on white).
  • Overlay: scrim behind dialogs and the search palette.

Typography

Three faces, one geometric family feel: wide and round where the brand speaks, compact and plain where people work.

  • Unbounded (font-display) for the wordmark and the few lines where the brand speaks: display (login, empty states), title-1 (page titles), title-2 (record titles). It is wide, so keep it to short, single lines and never use it below 18px or for running text. Its round U echoes the mark.
  • Instrument Sans (font-sans) for everything people read and scan: title-3 for panel headings, body (14px) as the default, body-lg for ticket descriptions and comments, label for buttons, labels and nav, small for metadata, caption (uppercase, tracked) for table headers, badges and nav sections.
  • Martian Mono (font-mono) for anything a technician copies or compares: record-id for record IDs, mono for serials, MAC and IP addresses, hostnames and the app version. It runs wide, so it is set a step smaller than the text around it.
  • Use tabular figures for numbers in tables and counters.
  • Font files live in fonts/ (latin subsets, woff2). Add the latin-ext subsets in the app if names with less common diacritics appear.

Spacing, radius, elevation

  • 4px base: space-1 to space-12. Controls pad space-3 inline; panels pad space-4; page gutters are space-6.
  • Heights: size-control-md (36px) for buttons and inputs, size-control-sm in tables and toolbars, size-control-lg on the login form. Table rows size-row (40px) or size-row-compact (32px).
  • Radius echoes the mark's round caps: radius-sm chips and badges, radius-md controls, radius-lg panels and dialogs, radius-full avatars and dots.
  • Elevation: borders first. shadow-md only for popovers and menus, shadow-lg for dialogs and the search palette over scrim.

States and motion

  • Hover: surface-2 on neutral elements, brand-hover on brand fills.
  • Focus on controls (buttons, tabs, checkboxes, switches, close buttons): a 1px solid focus outline with 2px offset, keyboard only (:focus-visible).
  • Focus on text-like fields (inputs, textareas, selects, input groups): the field's own 1px border turns focus, with a faint 2px focus halo at 12% alpha. The solid border carries the 3:1; the halo is decorative.
  • Selected: brand-soft background with brand or ink text.
  • Disabled: 50% opacity, not-allowed cursor, never the only way to explain why an action is unavailable.
  • Motion is functional: 120 to 160ms ease-out for menus, dialogs and row expansion; nothing decorative; respect prefers-reduced-motion.

Layout

  • AppShell: sidebar at size-sidebar with Search, the three modules, Directory and Settings plus the app version at the bottom. Content on surface-0.
  • List pages: title-1 header with a one-line live summary and one primary action, then filters, then a DataTable.
  • Detail pages: see TicketDetailLayout. A top bar (breadcrumb, global search, notifications, user), a record header (ID chip, status, SLA, title-2, one line of provenance, actions on the right), a view toggle, then a two-column grid: the conversation or activity on the left, a 340px column on the right with Details, RelatedRecords and, for assets, AssetTimeline. Assets and projects use the same skeleton.
  • GlobalSearch (⌘K / Ctrl K) searches every record type at once and groups results by module.

Iconography

Lucide (lucide-svelte), stroke icons on a 24px grid, inheriting currentColor. 16px in controls and tables, 20px in navigation. Each module has one fixed icon: monitor Assets, ticket Service desk, folder-kanban Projects, waypoints relations, users Directory. No emoji, no filled or duotone icons. Reference set and asset-type icons in assets/Icons/README.md.

Logo

Every file below is the final vector. Use the SVG buttons to download each one.

The mark is a U drawn as one thick stroke, split into two stems and joined by a dot: blue stem for assets, green stem for projects, violet dot for the service desk, the point where the two meet. It is built from exact geometry, so every edge lines up. unitati-concept-u.png is the concept it comes from.

Construction, in the mark's own 250 × 220 units:

  • Stems 80 wide, 90 apart (x 0 to 80 and 170 to 250), with round caps of radius 40. Both stems start at y = 0.
  • The bottom of the U is one stroke: the inner and outer arcs share a centre (125, 100), radii 45 and 125. So the stroke keeps the same 80 width all the way round.
  • The dot has radius 40 (as wide as a stem) and sits at (125, 180). A ring of 14 units cut out around it (radius 54) separates it from the stems.
  • The tips of both stems and the bottom of the dot all end on the same line, y = 220.
  • Colors: blue stem #17a7fd to #0d62fc, green stem #28d5a4 to #1aaf94, dot #7a4cf8 to #6a3df6, all top to bottom.

Files:

  • unitati-mark.svg: full-color mark. Use on surface-0, surface-1 and dark grounds. Minimum size 16px; clear space on every side of at least half a stem (40 units).
  • unitati-mark-ink.svg, unitati-mark-white.svg: single ink #0F1720 or #FFFFFF, with the ring cut out so it works on any ground.
  • unitati-lockup.svg, unitati-lockup-inverse.svg: mark plus wordmark. Cap height is 60% of the mark's height and the capitals are centred on it; the gap between mark and name is 50 units (five eighths of a stem).
  • unitati-lockup-tagline.svg, unitati-lockup-tagline-inverse.svg: compact lockup. The text block spans the mark exactly: the top of the wordmark meets the top of the stems, and the tagline's baseline meets the bottom of the mark. The tagline (Instrument Sans, #566171 on light, #98A3B3 on dark) is as wide as the wordmark.
  • unitati-wordmark-ink.svg, unitati-wordmark-white.svg: the name alone, Unbounded Bold (700) outlined, tracked -0.02em. Its U repeats the shape of the mark.
  • unitati-app-icon.svg (white tile with hairline), unitati-app-icon-dark.svg (#0F1720 tile), unitati-app-icon-violet.svg (violet gradient tile, white mark): rounded square with corner radius 22.5%, mark 60% of the tile width, centred.

Never recolor the stems or the dot, close the ring, change the proportions, rotate, add effects, or set the name in another face.

Components

Reference rendering of each component with its usage guide. Class names use the ut- prefix; rebuild them as Svelte components on shadcn-svelte.

Actions

Button

primary, secondary, ghost, danger, toggle; sm, md, lg

Triggers an action. A pill, like the round caps of the mark; when it carries an icon, the icon sits in a disc, like the mark's dot. Maps to shadcn-svelte Button, restyled; the variants below are the only ones the app uses.

Consumer provides: a verb-first label (sentence case, max three words), an optional Lucide icon wrapped in ut-btn-dot, an optional keyboard shortcut in ut-btn-kbd, and the handler.

Variant Class Use
Primary ut-btn-primary The one main action of a view: New ticket, Save, Sign in. action fill, on-action text, icon disc in action-accent. One per region.
Secondary ut-btn-secondary Every other action: Link asset, Export CSV, Assign to me. surface-1 with a border-strong ring.
Ghost ut-btn-ghost Toolbar and dialog dismiss actions, icon-only buttons.
Danger ut-btn-danger Irreversible actions (Retire asset, Delete project), always behind a confirmation dialog.
Toggle group ut-btn-group Switching views of the same data (Queue / Board / Calendar). The pressed item is a raised surface-1 pill with aria-pressed="true".

Anatomy and behaviour:

  • Shape radius-full; label label weight 600; gap space-2.
  • Icon disc: 26px (20px in sm, 28px in lg), icon 14px at stroke 2.25. It is optional: a button without an icon is just the pill.
  • Shortcut chip: Martian Mono 10px on a 14% tint of the label colour. Show it on the primary action of each module (N for New ticket) so technicians learn the keyboard.
  • Primary and danger have a 2px darker lip at the bottom; on press the lip goes and the button drops 1px. Motion is off under prefers-reduced-motion.
  • Busy: keep the label, disable the button, and the disc becomes a spinner (ut-btn-busy).
  • Sizes: ut-btn-sm (size-control-sm, in tables and toolbars), default (size-control-md), ut-btn-lg (size-control-lg, login and empty states).

Do and don't:

  • Do write the outcome: Close ticket, not Submit.
  • Do give icon-only buttons an aria-label and a tooltip.
  • Don't put two primary buttons side by side; don't use danger for Cancel; don't colour buttons with domain colours.

Forms

Field

default, with help, error

A label, a control and optional help or error text, stacked. Wraps shadcn-svelte Input, Select and Textarea; validation comes from superforms + zod.

Consumer provides: label (always visible, never placeholder-only), the control, optional help, and the error string from the form schema.

  • Label in label style, help and error in small. Gap space-1 inside a field, space-3 between fields.
  • Error state: danger border plus an error line that starts with circle-alert and says how to fix it.
  • Serials, MACs, IPs and hostnames use font-mono inside the input.
  • Dates and numbers follow the user's locale (es/ca: 31/12/2026, 1.234,50).

RelatedRecords

relation panel on a ticket

The side panel on every detail view that lists the records linked to this one, grouped by relation. It reads from the links domain; it is where "full context" becomes visible.

Consumer provides: the current record and its groups: each with a relation label (Affected asset, Project task, Tickets on this asset, People), an icon, and the linked items, each with an optional trailing badge or meta line.

  • Panel: surface-1, border, radius-lg; header in title-3 with a ghost Link action.
  • Group labels in caption, uppercase, ink-muted, with the domain icon.
  • Items are RecordRefs or Avatar person rows. One useful fact under an item (ticket count, warranty date) in small.
  • Order: asset, tickets, project, people. Hide empty groups; show the Link action instead.

AssetTimeline

incident history of one asset

The history of one asset, newest first: tickets raised on it, repairs, reassignments and the projects that touched it. It answers "what has happened to this machine" without leaving the asset page.

Consumer provides: a list of events, each with kind (ticket, asset, project), an icon, an optional RecordRef, a status badge, and a timestamp.

  • Dots are 28px discs in the domain's *-soft with the domain color icon; the rail is border at 2px.

  • Events without a record (repair, owner change) show a plain sentence in body-strong.

Data

DataTable

ticket queue, selected row

Layout: ticket detail

Reference layout for a record detail page, shown with a ticket: the screen where "full context" has to be true. Asset and project detail pages use the same skeleton with their own main column.

Consumer provides: the record, its conversation or activity, its details, its links (from the links domain) and, when an asset is linked, that asset's history.

Structure, top to bottom:

  • AppShell sidebar on the left, current module highlighted.
  • Top bar, 56px: breadcrumb (module / view / record ID in record-id), the global search pill with ⌘K, notifications and the user's avatar.
  • Record header: RecordRef ID chip, StatusBadges, SLA countdown (Martian Mono, warning with a small progress bar), the title in title-2, one small line of provenance (who, when, channel). Actions on the right: secondary first, the primary last, with its keyboard shortcut.
  • View toggle (ut-btn-group): Conversation, Activity, Linked · n.
  • Two columns, space-6 apart: main column fluid; side column 340px.
  • Main: the thread. Replies with avatar, name and time; internal notes on warning-soft with an Internal note badge; system events (a link created, a status change) as one muted line with the RecordRef inline. The composer sits at the end of the thread, with Internal note as a toggle and the primary Send reply (⌘↵).
  • Side: Details as a definition list (ut-dl), RelatedRecords, then Asset history (AssetTimeline) for the linked asset.

Rules:

  • Every record mentioned anywhere on the page is a RecordRef, so the user can jump across modules from any line.
